# 장원 별밤학교 PDF 접수기

지정 폴더: https://drive.google.com/drive/folders/1nVOwpeKQ5URIGDwiOmECRaJZTWBEUEPk

이 코드는 Firebase 없이 최종 PDF 한 파일만 받습니다. 사진 개별 파일·진행 상태를 자동으로 수집하지 않습니다. 사진 7장, 이름·학년·소감을 보호자가 확인하고 제출을 눌러야 전송합니다.

## 선생님 Google 계정에서 한 번만 설정

1. Google Apps Script에서 새 프로젝트를 만듭니다. 이름은 `장원 별밤학교 PDF 접수기`로 설정합니다.
2. 기본 `Code.gs`를 이 폴더의 `Code.gs` 전체 내용으로 바꿉니다. 별도 라이브러리나 API 키가 필요 없습니다.
3. `checkUploadFolder` 함수를 실행합니다. 지정 폴더를 사용할 수 있는 선생님 계정으로 Google 권한 화면을 검토하고 승인합니다. 이 코드는 지정 폴더에만 쓰지만 Google의 DriveApp 권한은 Drive 전체 접근 범위로 표시될 수 있습니다. 승인 여부는 선생님이 직접 결정합니다.
4. **배포 → 새 배포 → 유형: 웹 앱**을 선택합니다. 실행 사용자는 **나**, 액세스 사용자는 **모든 사용자**로 설정합니다. 학생은 Google 로그인을 하지 않습니다. 학교 계정 정책상 익명 웹 앱을 허용하지 않으면 이 방식은 활성화할 수 없습니다.
5. 배포 결과의 `/exec`로 끝나는 웹 앱 URL을 전달합니다. 개발용 `/dev` URL은 사용하지 않습니다.
6. 해당 주소를 `src/data/driveUploadConfig.ts`의 `DRIVE_UPLOAD_ENDPOINT`에 설정하고 Sites 빌드·배포를 실행합니다. 현재는 아래 `/exec` 주소가 설정되어 있습니다.
7. 실제 휴대폰으로 미션 7개 → 사진·소감 PDF 확인 → 보호자 동의 → 제출을 실행하고 위 지정 폴더의 파일을 확인합니다. 같은 내용으로 다시 제출했을 때 파일이 1개인지 확인합니다.

## 동작과 제한

- 10MB 이하의 PDF만 접수합니다. PDF 표지 시그니처와 마지막 EOF 표시를 검사합니다.
- 접수 마감: 2026년 10월 23일 00:00 (한국 시간). 최대 1,000건, 총 예약 용량 5GB. 필요하면 CONFIG를 수정하고 Apps Script 새 버전을 배포합니다.
- 같은 포트폴리오 내용은 같은 접수 ID로 확인합니다. ScriptLock과 예약 기록, 파일명 검색으로 중복 클릭·응답 유실 후 재시도를 처리합니다.
- POST는 교차 출처 제약 때문에 `no-cors`로 전송합니다. **POST 완료를 성공으로 판단하지 않습니다.** Google이 실제 파일을 만든 뒤 저장한 영수증을 별도 JSONP 조회로 받아야 ‘제출 완료’가 됩니다.
- 영수증 조회는 이름·사진·파일 ID·파일 URL을 반환하지 않습니다. 불규칙한 256비트 접수 ID와 상태만 반환하며 콜백 이름을 제한합니다. GET 요청으로 파일을 만들지 않습니다.
- 공개 접수 주소는 비밀 키가 아닙니다. 위 용량·건수·마감 제한을 두며 파일 목록이나 다운로드를 노출하지 않습니다. Drive 폴더의 기존 공유 설정을 변경하지 않습니다.
- Apps Script 동시 실행·Google Drive 용량·계정 정책·현장 통신 상황에 따라 지연/실패할 수 있습니다. 확인이 늦으면 ‘미확인’으로 남고 PDF 기기 저장 경로를 안내합니다. 실제 Google 서버·휴대폰 전송 검증은 배포와 권한 승인이 끝난 뒤 필요합니다.

## 최신 수정본(v3) - 이미 배포한 경우

웹앱에서 `학교_학년_반_이름.pdf`로 최종 저장하려면 이 폴더의 최신 `Code.gs`로 기존 코드를 교체하고 저장한 뒤, **배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포**를 실행합니다. 기존 배포를 수정하면 `/exec` 주소를 그대로 사용할 수 있습니다. 이름 변경 전에 내부 기록에 Drive 파일 ID를 저장하므로 중복 방지 번호가 최종 파일명에 보이지 않아도 재시도를 안전하게 처리합니다.

최신 기본 응답은 `{"service":"jangwon-final-pdf","version":3}`입니다. 기존 클라이언트는 v2 이상과 호환되며 v1 접수기에 파일을 보내지 않습니다. 코드 저장만으로 기존 `/exec`가 업데이트되지 않으므로 반드시 새 버전을 선택해 기존 배포를 수정합니다. 기존 파일이나 스크립트 속성을 삭제할 필요가 없습니다.

v3 수정 사항:
- 한 PDF가 남은 용량보다 크다는 이유로 모든 참가자의 접수를 닫던 v2의 전역 `closed` 표시를 사용하지 않습니다. 현재 건수·예약 용량·마감 시각으로 판단합니다.
- 마감 후 실패한 예약을 재전송하면 JSONP 상태도 `rejected`로 갱신됩니다. 이미 생성된 파일의 이름 변경·영수증 복구는 마감 후에도 중복 생성 없이 완료합니다.
- 손상된 접수 기록·건수·용량은 새 파일을 만들지 않고 제한된 오류 코드로 응답합니다. 기존 v1/v2의 saved 기록은 유지합니다.
- 잘못된 JSON·PDF는 POST 응답에서 재시도 대기가 아닌 거절로 구분합니다. 불투명 POST만으로 완료 처리하지 않는 원칙은 유지합니다.
- 파일명은 클라이언트가 만드는 최대 243자 본문까지 보존하며, 재전송 중 입력 파일명이 달라져도 처음 예약한 이름을 유지합니다. 준비 파일명은 접수 ID로 만들어 긴 이름과 분리합니다.

주소를 열 때 Google의 ‘현재 파일을 열 수 없습니다’ 화면이 보이는 현상은 위 업로드 처리 오류와 직접적인 인과가 확인되지 않았습니다. GET 기본 응답은 Drive에 접근하지 않으므로 JSON 응답·리디렉션·계정/배포 접근 문제를 별도로 확인해야 합니다.
